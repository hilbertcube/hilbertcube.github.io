# CSS Organization

Sitewide styles live in `src/assets/css/`, bundled through `main.css` and imported once by
`BaseLayout`. Rules that belong to one component live in that component's scoped
`<style>` instead (see [`COMPONENTS.md` §0](COMPONENTS.md#0-conventions)),
so this tree only holds what has no single owner.

```text
src/assets/css/
├── main.css               Import manifest — the only file BaseLayout imports
├── base/
│   ├── _variables.css     Every --custom-property, plus the dark-mode overrides
│   ├── _fonts.css         @font-face declarations (fonts self-hosted under public/assets/fonts/)
│   ├── _reset.css         Browser normalisation and base element styles
│   └── _typography.css    Headings, body links, figure/table caption numbering, .topic
├── layout/
│   └── _grid.css          Page structure: .general-wrapper, .content-grid
├── components/
│   ├── _search.css        Pagefind's highlight marks on the destination page
│   ├── _sidebar.css       The sidebar shell and its section headers
│   ├── _math.css          .equation, KaTeX tweaks, theorem/problem/definition/lemma boxes
│   ├── _code-blocks.css   Code containers and .shiki base rules (per-theme colours are generated by codeThemeCss() in src/utils/codeThemes.ts)
│   └── _content.css       Body lists and other shared content elements
├── pages/
│   └── _home.css          .home-title (homepage, About, FeatureSlider)
└── utils/
    ├── _print.css         @media print layout (Save as PDF button, npm run pdf)
    └── _responsive.css    Sitewide media queries, largest breakpoint first
```

## Import order

`main.css` imports **base → layout → components → pages → utils**. Later files win
ties, which is why `_responsive.css` comes last: its breakpoint rules override
the desktop defaults above them without `!important`.

## Conventions

- **Use the custom properties** in `base/_variables.css` instead of hard-coded
  colours and sizes. Dark mode is a `dark-mode` class on `<html>` that redefines
  them, so a rule written against the variables is theme-aware for free.
- **Readers override fonts, sizes and code themes at runtime** from the settings
  panel (inline styles and `data-code-light` / `data-code-dark` on `<html>`).
  Don't fight them with `!important`.
- **Markup one component owns is styled in that component**, not here — e.g.
  the search bar, results and hamburger in `TopBar.css`, `.title` in
  `PageTitle`, `.date` in `PubDate`, `.proof` / `.solution` in `Proof` / `Solution`. Rules for slot
  content or runtime-built nodes need `:global()`.
- **Media queries:** sitewide ones go in `utils/_responsive.css`; a component's
  breakpoints stay in its scoped `<style>`. They must move with the rule: a
  scoped rule outranks a global media query, which then silently stops working.
- **Page-specific CSS** goes in the page's `head` slot, not here.
- **New partial:** name it `_name.css` in the folder matching its role, and add
  an `@import` to `main.css` in that section.
